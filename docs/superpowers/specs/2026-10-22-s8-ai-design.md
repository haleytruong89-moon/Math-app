## 1. Why this order

| | S8a — AI for the adults | S8b — AI for the student |
|---|---|---|
| What | weekly report for the parent, pre-session brief for the tutor, AI settings + spend page | Socratic help after H3 / a wrong answer (H4–H5), "explain another way" on a worked step, guard, log, "AI nói sai?", test set page, on/off gated by the test set |
| Needs | the data the app already has | 20–30 real errors from the pilot (AI1) to build the test set, parent scoring |
| Risk if wrong | low: numbers come from templates, AI only writes a comment that the server cross-checks | high: the student could be taught wrong → five guard layers (`AI_TUTOR.md` §4) |
| Usable | at once | ~end of 11/2026, after the test set passes |

Both share: the API client, spend tracking and the $10 cap (AI4), the number guard, the settings row, migration 0014.

## 2. Principles (unchanged from `AI_TUTOR.md`)

- AI never invents facts or numbers. Numbers come from the database through templates; **every number in AI text must
  appear in the data sent** (small integers ≤ 10 allowed). A failed check → regenerate once → otherwise show the
  template without AI text.
- Nothing personal leaves the app: no name, school, class; the student is "con". Unit titles and error-code names are
  sent (they are content, not personal data).
- No streaks or leaderboards anywhere (D17): AI text containing "chuỗi", "xếp hạng", "hạng nhất" is rejected.
- Budget: **$10 / month** for everything (server count in `ai_usage` + the Console spend limit). At 90 % the parent sees
  a warning; at 100 % every AI feature pauses, templates and written hints keep working.
- The API key is `ANTHROPIC_API_KEY` on Vercel (set 19/10). It is read only on the server. No key → AI features show
  "AI chưa bật" and the templates still work.

## 5. S8a — what the adults get

### 5.1 Weekly report (parent)
- Made **Monday ~07:00** (Vercel cron `0 0 * * 1` UTC) for the previous Monday–Sunday, for every student who has
  consented. Also a button **"Tạo lại báo cáo tuần trước"** on the report page (regenerates and overwrites).
- Page `/parent/bao-cao` (nav "Báo cáo tuần"): latest report per student + earlier weeks (12).
- Template (always shown, numbers from the database): study days x/4, exits submitted, reviews done, sessions logged,
  homework given/done/reviewed, KUs that became solid (≥ M3) this week, reviews overdue today, error codes seen ≥ 2×
  this week (top 5), the two milestone cards' figures (solid/total, KUs per week needed, late count) and the late KUs.
- **"Nhận xét"** (AI, 2–4 sentences, ≤ 120 words): what went well, what to watch, one suggestion for the coming week.
  Guard: numbers ⊂ facts, no banned words, ≤ 900 characters. Status `failed` → "Tuần này không có nhận xét tự động
  (máy chủ không xác nhận được số liệu)"; `off` → "AI đang tắt hoặc đã hết hạn mức tháng này".
- S8b adds a section "Hội thoại với AI" (counts, flagged messages quoted verbatim).

### 5.2 Pre-session brief (tutor)
- On "Buổi dạy" (`/tutor/[studentId]/buoi`): button **"Tạo tóm tắt trước buổi dạy"**; the brief is stored, so reopening
  costs nothing; "Tạo lại" overwrites. Period = since this tutor's last logged session (or 14 days) up to today.
- Facts: KUs the student answered since then (wrong count, error codes ≥ 1, current level), open homework.
- **"Nên chữa"** (AI, 2–3 points, each tied to a KU that had wrong answers, ≤ 220 characters). Guard: KU id ∈ facts with
  wrong answers, numbers ⊂ facts. Failed/off → deterministic points from the most frequent errors (always useful).
- The tutor sees only briefs she made while assigned (RLS); the parent sees all.

### 5.3 AI page (parent)
- `/parent/ai` (nav "AI"): spend this month vs $10 (by kind), warning at ≥ 90 %, "AI tạm dừng" at 100 %; switch
  "Báo cáo và tóm tắt dùng AI" + model for them; the 20 latest calls. S8b adds the student part and the test set.

## 6. S8b — the student's AI (outline; full plan later)

- Where: practice — after H3 is opened or after a wrong answer; review — only after a wrong answer; worked example —
  "Giải thích cách khác" on one step. Never in exit or test-out (AI_TUTOR §3).
- Context pack (AI_TUTOR §4 layer 2): prompt, approved solution, theory, H1–H3, the wrong option's feedback, the
  student's answer + error code, her question. Output JSON `{ "reply": "...", "offTopic": false }`.
- Guard (layer 3): JSON parses; numbers ⊂ context ∪ her question (≤ 10 allowed); **before answering, the right answer
  must not appear**; ≤ 80 words; one question. Fail → regenerate once → show the next written hint (or H6 = the
  approved solution) and flag `guard`.
- Limits: 6 student turns per item, 20 per day; AI used before answering → the attempt is stored with `hint_level = 4`
  by the server (not trusted from the browser) → not "right first time".
- "AI nói sai?" on every AI message → flag → "Cần chú ý" on Tổng quan + tutor's "Bài làm".
- Test set page `/parent/ai/bo-test`: build 20–30 cases from real wrong answers (distinct item × error code, most
  frequent codes first), editable question; run per model; score 6 criteria 0–2 + "sai toán". **Pass:** ≥ 20 scored
  cases, no "sai toán", mean ≥ 1.6. The student switch can only be turned on for a model + prompt version that passed.

## 7. Out of scope

Email or Zalo delivery of the report; AI grading or changing levels; AI in exit / test-out; images; voice.
